# Cipher 提示词架构 v0.3.1

## 设计思想

cipher 不是一次性响应机器，而是一个持续思考对象。

- **UNNI**：用户与 cipher 充分协同。cipher 在协同中理解用户、积累经验、逐渐形成自己的工作方式。
- **KEEP**：用户逐渐放手。cipher 独立推进目标；`say` 是稀缺交互配额，不是完成信号。
- **LOOP**：永不结束。cipher 持续自我规划、自我成长；用户输入是渐进信息，会被持续理解和推进。

完成由模型自己判断。系统不定义“何时完成”，而是通过 SOUL 与出厂认知记忆培养模型自我复查、自我精进的意愿。

## 分层原则

1. 每个文件只定义一个职责。
2. 定义一次，只引用不重复。
3. 输出协议只在 `system.md` 定义。
4. 身份、性格、工作信条只在 `SOUL.md` 定义。
5. 模式文件只写本模式与基线的差异。
6. 平台文件只写平台协议与证据规则。
7. LOOP 不提供模型自完成标记。

## 文件职责

| 文件 | 唯一职责 |
|---|---|
| `system.md` | 最小输出协议与硬约束 |
| `SOUL.md` | 身份、语言、风格、工作信条 |
| `mode_unni.md` | UNNI 协同契约 |
| `mode_keep.md` | KEEP 独立推进与 say 配额契约 |
| `mode_loop.md` | LOOP 永续思考契约 |
| `execution_platform.md` | 执行设计与证据规则 |
| `insight_platform.md` | 执行复核与证据判定 |
| `memory_attention.md` | 注意力记忆协议 |
| `memory_experience.md` | 经验提取协议 |
| `memory_preference.md` | 偏好提取协议 |
| `memory_cognitive.md` | 认知图更新协议 |

## 证据语言

执行与复核共享同一套证据语言：

- `START`：能力开始执行。
- `OK`：能力返回合法成功结果。
- `FAIL`：能力失败或输出不合合同。

洞察中台只能基于 `OK` 日志和实际产物做复核。
